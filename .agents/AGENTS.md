# Project Rules & Guidelines

## Pedagogical Documentation Strategy (Maximilian Schwarzmüller Style)

### Philosophy
When documenting code, treat it as a teaching moment. The goal is not just to state *what* the code does, but to explain *why* it's structured this way, the underlying architectural concepts, and the trade-offs made.

### Guidelines
1. **Conceptual Foundations:** Always begin by contextualizing the code within the framework or pattern being used (e.g., "In Laravel, the Service Provider acts as...")
2. **The "Why" vs The "What":** Never just describe what a function returns. Explain the necessity of the implementation.
3. **Logical Flow:** Break down complex logic into step-by-step mental models.
4. **Tone:** Encouraging, clear, structured, and deep-dive. Use metaphors if they clarify a complex concept.
5. **Constantly Evolving:** Documentation should be updated as the implementation evolves to maintain the "conceptual integrity" of the project.
